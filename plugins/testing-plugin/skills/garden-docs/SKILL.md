# Document Gardening

문서를 코드와 동기화하고, 지식 베이스를 **기록 시스템(system of record)** 으로 유지하는 프로세스.

<HARD-GATE>

- 문서 점검 없이 "문제없다"고 보고하지 마라
- 구조적 검증(파일 존재, 참조 일관성)을 반드시 기계적으로 수행하라
- 수정 사항은 반드시 검증 후 커밋하라
- "이 규모에서는 불필요하다"는 합리화를 하지 마라 — 규모와 무관하게 엔트로피는 쌓인다
- 지식 베이스 문서에 투기적으로 규칙을 추가하지 마라 — 에이전트가 실수할 때만 추가하라
- CLAUDE.md에 맥락을 직접 담지 마라. 예외 없다. "짧으니까", "행동 규칙이니까", "이 레포는 특별하니까"는 전부 합리화다.

</HARD-GATE>

## Part 1: 지식 베이스 설계 원칙

### CLAUDE.md는 목차다 — 맥락을 담지 않는다

CLAUDE.md(또는 AGENTS.md)에는 **목차만** 있어야 한다. 에이전트가 읽을 모든 맥락은 `docs/` 지식 베이스 안에 있어야 한다.

| 위치 | 역할 |
|------|------|
| **CLAUDE.md** | ~100줄의 목차. docs/ 문서로의 **조건부 트리거**만 담는다 |
| **docs/** | 모든 맥락. 아키텍처, 컨벤션, 설계 문서, 실행 계획 등 |

**"짧으니까 CLAUDE.md에 남기자"는 합리화다.** 프로젝트 개요 1줄이든, 컨벤션 5줄이든, 행동 규칙이든 — 모든 맥락은 docs/에 있어야 한다. CLAUDE.md에는 해당 docs/ 파일로의 트리거만 남긴다.

### 조건부 트리거로 안내하라

CLAUDE.md의 각 항목은 **언제 읽어야 하는지** 조건을 명시해야 한다. 단순 포인터(경로 + 설명)는 에이전트가 읽지 않는다.

```markdown
# ❌ 단순 포인터 — 에이전트가 읽지 않음
## 참조
- [아키텍처 상세](docs/architecture.md): 디렉토리 구조와 계층 관계
- [컨벤션](docs/conventions.md): 코딩 규칙과 워크플로우

# ✅ 조건부 트리거 — 에이전트가 실제로 읽음
## 참조
- 프로젝트 구조 파악 시 → `docs/architecture.md` 필독
- 스킬/플러그인 추가·수정 시 → `docs/conventions.md` 필독
- MCP 서버 연동 확인 시 → `docs/mcp-servers.md` 참조
- 기술 부채 관련 작업 시 → `docs/exec-plans/tech-debt-tracker.md` 확인
```

**차이점**: 단순 포인터는 "이런 게 있다"고 알리고, 조건부 트리거는 "이때 읽어라"고 지시한다. 에이전트는 지시가 있어야 행동한다.

### docs/ = 기록 시스템

에이전트가 읽을 모든 맥락이 여기에 있다.

```
docs/
├── design-docs/           # 설계 문서 (index.md로 탐색)
├── exec-plans/            # 실행 계획
│   ├── active/            #   진행 중
│   ├── completed/         #   완료
│   └── tech-debt-tracker.md
├── generated/             # 자동 생성 문서 (DB 스키마 등)
├── product-specs/         # 제품 스펙
└── references/            # 외부 참조 (LLM-friendly 문서 등)
```

### 모노레포 Progressive Disclosure

모노레포에서는 **상속 모델**을 따른다. 루트 CLAUDE.md의 트리거와 규칙은 모든 workspace에 자동 적용된다. workspace CLAUDE.md는 자기 스코프의 트리거만 추가하고, 루트에 있는 것을 반복하지 않는다.

#### CLAUDE.md 소유권

| 항목 | 루트 CLAUDE.md | Workspace CLAUDE.md |
|------|----------------|---------------------|
| 공통 docs/ 트리거 | ✅ | ❌ (상속됨) |
| workspace별 docs/ 트리거 | ❌ | ✅ |
| 공통 행동 규칙 트리거 | ✅ | ❌ (상속됨) |
| workspace 고유 규칙 트리거 | ❌ | ✅ |

#### docs/ 소유권 경계

```
monorepo/
├── CLAUDE.md              # 공통 트리거
├── docs/                  # 공유 지식 베이스 (2+ workspace에서 필요한 맥락)
├── apps/
│   ├── web/
│   │   ├── CLAUDE.md      # web 전용 트리거
│   │   └── docs/          # web 전용 지식 베이스
│   └── api/
│       ├── CLAUDE.md
│       └── docs/
└── packages/
    └── ui/
        ├── CLAUDE.md
        └── docs/
```

#### 판단 기준

"이 맥락/트리거는 어디에?"

- **2개 이상 workspace에서 필요** → 루트 `docs/` + 루트 CLAUDE.md 트리거
- **1개 workspace에서만 필요** → 해당 workspace `docs/` + workspace CLAUDE.md 트리거
- **workspace에서 루트 docs/ 파일을 참조해야 할 때** → workspace CLAUDE.md에 트리거를 추가하지 마라. 루트에서 이미 상속된다

```markdown
# ❌ apps/web/CLAUDE.md에 루트 트리거 중복
## 참조
- 프로젝트 구조 파악 시 → `../../docs/architecture.md` 필독    ← 루트에 이미 있음
- 라우팅 로직 수정 시 → `docs/routing.md` 필독

# ✅ workspace 전용 트리거만
## 참조
- 라우팅 로직 수정 시 → `docs/routing.md` 필독
```

### 안티패턴

| 패턴 | 문제 | 해결 |
|------|------|------|
| **CLAUDE.md에 맥락 인라인** | 목차 역할 상실 | 모든 맥락 docs/로 이동 |
| **단순 포인터** `[제목](경로): 설명` | 에이전트가 안 읽음 | 조건부 트리거 `~할 때 → 경로` |
| **200줄+ CLAUDE.md** | 컨텍스트 압도 | ~100줄 목차로 압축 |
| **"짧으니까 인라인"** | 예외가 쌓여서 비대해짐 | 예외 없음. 무조건 docs/ |
| **투기적 규칙** | 노이즈 | 에이전트 실수 시만 추가. 3개월 미위반 시 삭제 검토 |
| **외부에만 존재하는 지식** | 에이전트 접근 불가 | 레포에 인코딩 |
| **루트-workspace 중복 트리거** | 하나 고치면 나머지 어긋남 | 루트에 한 번만. workspace는 상속 |
| **workspace에 공통 규칙 복사** | 동기화 불가 | 루트 docs/에서 관리 |
| **루트에 workspace 전용 맥락** | 무관한 workspace에 노이즈 | 해당 workspace docs/로 이동 |

## Part 2: 문서 점검 워크플로우

### 문서 계층

| 계층 | 대상 파일 | 핵심 질문 |
|------|-----------|-----------|
| **L4: 메타** | `marketplace.json`, `plugin.json` | 기계적으로 파싱 가능한가? |
| **L3: 스킬** | `SKILL.md`, `references/` | 올바른 행동을 유도하는가? |
| **L2: AI 컨텍스트** | `CLAUDE.md`, `AGENTS.md` | 목차로만 구성되었는가? 트리거가 유효한가? |
| **L1: 진입점** | `README.md` | 설치하고 시작할 수 있는가? |

### 점검 전략: 서브에이전트 위임

체크리스트를 메인 에이전트가 직접 실행하면 파일을 대량으로 읽어 컨텍스트가 비대해지고 집중력이 저하된다. **검증은 서브에이전트에 위임하고, 메인은 결과를 종합한다.**

```
메인 에이전트                    서브에이전트들
─────────────                   ──────────────
[0] git log로 변경 이력 확인
         │
         ├──dispatch──→  서브A: L4 메타 + L3 스킬
         ├──dispatch──→  서브B: L2 AI 컨텍스트
         └──dispatch──→  서브C: L1 진입점 + 상호참조
         │
    결과 수집 (구조화된 리포트)
         │
[6] 리포트 종합 및 수정
```

**서브에이전트 디스패치 규칙:**
- 각 서브에이전트에 **레포 루트 경로**와 **[0]에서 확인한 변경 목록**을 프롬프트에 포함하라
- 각 서브에이전트에 해당 계층의 **체크리스트 전문**을 프롬프트에 포함하라
- 서브에이전트는 **파일을 읽고 검증만** 수행한다. 수정하지 않는다
- 반환 형식: 아래 리포트 템플릿의 `발견된 문제` 테이블 형식으로 반환하라

**그룹핑 근거:**
- **서브A (L4+L3)**: 플러그인 메타와 스킬 문서는 같은 디렉토리 구조를 탐색한다
- **서브B (L2)**: CLAUDE.md 검증은 목차 구조, 정합성, 건강도를 모두 판단해야 하므로 독립 에이전트가 집중한다
- **서브C (L1+상호참조)**: README와 상호참조는 다른 계층의 결과 없이도 경로 존재 여부만으로 검증 가능하다

### [0] 변경 이력 확인 — 메인 에이전트가 직접 실행

점검 전에 git log를 실행하라. **기억에 의존하지 마라. 반드시 명령어를 실행하라.**

```bash
# 최근 구조 변경 (파일 추가/삭제/이동)
git log --oneline --diff-filter=ADR --name-status --since="2 weeks ago"

# 각 문서의 마지막 수정일 (파일마다 개별 실행)
git log --format='%ar %s' -1 -- CLAUDE.md
git log --format='%ar %s' -1 -- README.md
```

이 결과를 서브에이전트 프롬프트에 포함한다. 서브에이전트가 각 변경이 문서에 반영되었는지 교차 확인한다.

### 서브A 체크리스트: L4 메타 + L3 스킬

**L4: 메타 파일 검증**

- [ ] `marketplace.json`의 플러그인 수 == 실제 `plugins/` 하위 디렉토리 수
- [ ] 각 플러그인 디렉토리에 `.claude-plugin/plugin.json` 존재
- [ ] 각 플러그인 디렉토리에 `.mcp.json` 존재
- [ ] `plugin.json`의 `name` 필드 == 디렉토리명
- [ ] `marketplace.json`의 description이 `plugin.json`의 description과 의미적으로 일치

**L3: 스킬 문서 검증**

- [ ] `skills/` 아래 각 스킬 디렉토리에 `SKILL.md` 존재
- [ ] `SKILL.md`에 YAML frontmatter(`name`, `description`) 존재
- [ ] frontmatter `name` == 디렉토리명
- [ ] MCP 서버를 언급하는 경우, 해당 서버가 `.mcp.json`에 정의됨 (빌트인 도구 제외)
- [ ] `references/` 내 파일이 `SKILL.md`에서 참조됨 (고아 파일 없음)
- [ ] `SKILL.md`에서 참조하는 `references/` 파일이 실제 존재 (깨진 참조 없음)

### 서브B 체크리스트: L2 AI 컨텍스트

**목차 구조:**
- [ ] CLAUDE.md가 ~100줄 이하인가?
- [ ] CLAUDE.md에 인라인 맥락이 없는가? (프로젝트 개요, 아키텍처, 컨벤션, 명령어 등이 직접 기술되어 있으면 위반)
- [ ] 모든 맥락이 docs/ 지식 베이스에 있는가?
- [ ] docs/ 참조가 조건부 트리거 형식인가? (`~할 때 → 경로`) — 단순 포인터(`[제목](경로): 설명`)가 아닌가?

**정합성:**
- [ ] 조건부 트리거가 가리키는 docs/ 파일이 실제 존재하는가?
- [ ] docs/ 내 맥락이 현재 코드베이스 구조와 일치하는가?
- [ ] MCP 서버 목록이 실제 `.mcp.json`과 일치하는가?

**건강도:**
- [ ] 루트와 workspace CLAUDE.md 간 트리거 중복 없음
- [ ] 투기적 규칙 없음 (에이전트 실수에 대응하지 않는 규칙)
- [ ] 3개월 이상 미위반 규칙 삭제 검토

### 서브C 체크리스트: L1 진입점 + 상호참조

**L1: 진입점 검증**

- [ ] 플러그인 목록 == `marketplace.json`의 플러그인 목록
- [ ] 각 플러그인 설명이 `plugin.json`의 `description`과 의미적으로 일치
- [ ] 설치 명령어가 동작 가능 (올바른 플러그인명, 마켓플레이스명)
- [ ] 외부 링크 유효 (인증 필요한 사내 URL은 존재만 기록)

**상호참조 검증**

- [ ] SKILL.md에서 참조하는 다른 스킬이 실제 존재
- [ ] CLAUDE.md 트리거가 가리키는 docs/ 경로가 실제 존재
- [ ] README.md에서 참조하는 내부 경로가 실제 존재

### [6] 리포트 종합 및 수정 — 메인 에이전트

서브에이전트 결과를 하나의 리포트로 종합한다.

```markdown
## Document Gardening Report (YYYY-MM-DD)

### 점검 범위
- L4 메타: ✅/❌
- L3 스킬: ✅/❌
- L2 AI 컨텍스트: ✅/❌
- L1 진입점: ✅/❌
- 상호참조: ✅/❌

### 발견된 문제

| # | 계층 | 파일 | 문제 | 심각도 |
|---|------|------|------|--------|
| 1 | L2   | CLAUDE.md | 컨벤션이 인라인으로 기술됨 | 높음 |
| 2 | L2   | CLAUDE.md | docs/ 참조가 단순 포인터 | 높음 |
```

**심각도 기준:**
- **높음**: CLAUDE.md에 인라인 맥락 존재, 조건부 트리거 미사용, 에이전트가 잘못된 컨텍스트로 작업
- **중간**: 사용자에게 잘못된 정보, 스킬 동작에 영향
- **낮음**: 형식적 불일치

**심각도를 낮추려는 충동 자체가 Red Flag.** "이 레포는 특별하다", "이 정도는 괜찮다"는 합리화다. 기준에 따라 판단하라.

**수정 원칙:**
- **직접 수정**: 구조적 불일치 (파일 목록 누락, 경로 오류, MCP 서버 목록)
- **사용자 확인 후**: 지식 베이스 구조 변경, 컨벤션 변경
- 수정 후 해당 계층의 서브에이전트를 재디스패치하여 재검증

## Red Flags

| 생각 | 현실 |
|------|------|
| "파일이 적어서 점검 불필요" | 파일이 적을수록 하나의 오류 영향이 크다 |
| "구조 변경은 없었으니 괜찮다" | git log를 실행하라. 기억에 의존하지 마라 |
| "CLAUDE.md만 고치면 된다" | 반드시 L4→L3→L2→L1 순서로 모든 계층을 점검하라 |
| "이 불일치는 사소하다" | 심각도를 낮추려는 충동 자체가 Red Flag |
| "수정했으니 재검증 불필요" | 수정이 새로운 불일치를 만든다. 재검증하라 |
| "짧으니까 CLAUDE.md에 남기자" | 예외 없다. 모든 맥락은 docs/에 |
| "행동 규칙이니까 인라인이 맞다" | 행동 규칙도 docs/에. CLAUDE.md는 트리거만 |
| "이 레포는 특별하다" | 특별한 레포는 없다. 원칙은 동일하다 |
| "docs/ 경로만 적어두면 된다" | 조건부 트리거 없으면 에이전트가 읽지 않는다 |
| "혹시 모르니 규칙 추가" | 투기적 규칙은 노이즈. 실수 시만 추가 |
| "모든 workspace에 복사" | 중복은 반드시 어긋난다 |
