# skills

[English](./README.md) | 한국어

여러 프로젝트에 기여하면서도 어느 하나에 대한 이해를 잃지 않기 위한 개인용 에이전트 스킬. [Skills CLI](https://github.com/vercel-labs/skills)로 설치하며, Claude Code와 Codex 모두에서 동작합니다.

## 왜

프로젝트 사이를 오가는 데는 두 가지 비용이 듭니다: 프로젝트마다 도구 스택이 다르고(논의는 어디서, 작업 추적은 어디서, 배포는 어떻게), 에이전트가 코드베이스를 바꾸는 속도를 멘탈 모델이 못 따라갑니다.

## 철학

**충분히 이해한 결정만 코드베이스에 반영합니다.**
AI 시대에는 새 프로젝트를 쉽게 만들 수 있고, 완전히 독립적인 맥락 사이를 쉽게 오갈 수 있습니다 — 여러 프로젝트에 걸쳐 일하는 것이 새로운 기본값입니다. 동시에 그 모든 프로젝트가 AI를 활용한 기여로 채워지기에, 내가 직접 작업하는 코드베이스조차 이해도는 쉽게 떨어집니다. 하지만 코드베이스에 반영될 자격이 있는 결정은 충분한 이해 위에서 내린 결정뿐입니다. 그래서 이 스킬들은 내가 기여하는 모든 프로젝트의 이해도를 — 지금 하려는 작업이 요구하는 수준까지 — 끌어올리기 위해 존재합니다.

**이해는 작업 결과물 안에, 최대한 가까이에 둡니다.**
가장 좋은 코드베이스는 외부 맥락이 필요 없는 코드베이스입니다: 직관적인 코드와 구조 — 코드가 어쩔 수 없이 복잡하다면, 그것을 간결하게 잘 설명하는 주석. 그 다음은 맥락을 쉽게 찾을 수 있는 것: 잘 정리된 PR, 문서, 커밋 로그. 레포 밖 개인 저장소는 그 어디에도 담을 수 없는 맥락을 위한 최후의 수단입니다. 그래서 이 스킬들은 이해를 얻을 때마다 가능한 한 이 사다리 *위로* 밀어올립니다 — 어렵게 얻은 교훈은 코드 주석으로, 의사결정은 PR 설명으로 — 그리고 레포에 둘 곳이 없는 것만 개인적으로 보관합니다. 개인 저장소가 시간이 갈수록 줄어든다면, 코드베이스가 좋아지고 있다는 뜻입니다.

**대상 프로젝트에 흔적 0.**
이 스킬들이 아는 모든 것은 내가 소유한 개인 디렉터리에만 삽니다 — 기여하는 프로젝트에는 절대 남지 않습니다. 설정 파일도, `.gitignore` 항목도, 커밋도, 아무것도. 세팅은 레포가 아니라 *나*와 함께 이동합니다.

이것은 위생인 동시에 존중입니다. 사람마다 일하는 방식은 다 다르고, 이 스킬들조차 누군가에게는 맞지 않을 수 있습니다 — 그러니 스킬을 쓰지 않는 사람이 "이건 뭐지?" 하는 산출물과 마주쳐서는 안 됩니다. 남길 가치가 있는 유일한 흔적은 작업 결과물 그 자체이고, 이 스킬이 퍼진다면 *"이 사람은 어떻게 이렇게 생산성이 좋지?"*라는 궁금증을 통해서이기를 바랍니다.

## 스킬

### 루틴

세션을 여닫는 습관: 들어올 때 `/lets-work`, 나갈 때 `/checkpoint`. 모든 상태는 `${XDG_DATA_HOME:-$HOME/.local/share}/identity16-skills/` 아래에만 저장되며, 대상 프로젝트에는 절대 남지 않습니다.

| 스킬 | 하는 일 |
|---|---|
| `lets-work` | 세션 진입 의식. 마지막 방문 이후 프로젝트가 *내가 알던 모습*에서 얼마나 달라졌는지 브리핑하고(첫 방문이면 오리엔테이션), 세션의 작동 프레임을 설정합니다: 결정은 반영 전에 드러내고, 이해는 가장 오래 사는 곳에 두고, 팩의 도구들은 필요한 순간에 알아서 꺼내며, 나갈 때 `/checkpoint`를 제안. |
| `checkpoint` | 세션 퇴장 의식. 이번 세션에서 배운 것을 각자 있어야 할 곳 — 코드 주석, PR/커밋 메시지, 개인 저널 — 로 라우팅하고, 다음 `lets-work`가 브리핑할 방문 마커를 기록합니다. |

### 도구

필요한 순간에 꺼내 쓰는 스킬들. 커밋·PR·문서 등 레포 자체의 기록이 맥락을 더 많이 담게 만들어, 애초에 개인 저장소가 필요한 일을 줄입니다.

| 스킬 | 하는 일 |
|---|---|
| `organize-commits` | 브랜치를 리뷰어 친화적인 bisectable 커밋 시퀀스로 재구성합니다 — 모든 커밋이 독립적으로 빌드/테스트를 통과하고, 모든 메시지가 diff로는 알 수 없는 "왜"를 담도록. |
| `why` | 코드가 왜 이렇게 돼 있는지를 발굴합니다 — blame → 커밋 → PR → 이슈 순으로 파고들어 추측이 아닌 근거로 답합니다. 기록이 끊긴 지점은 잃어버린 맥락을 주석으로 복원하자는 제안으로 이어집니다. |
| `grill` | diff에 담긴 결정들을 ship 전에 인터뷰합니다 — 암기가 아닌 결과를 묻는 질문으로. 답 못한 결정은 라우팅됩니다: 코드가 스스로 설명하게 고치거나, 근거를 PR에 싣거나, 이해하고 나서 ship하거나. |

## 설치

```bash
# 어떤 스킬이 있는지 보기
npx skills add identity16/skills --list

# 이 레포의 모든 스킬 설치
npx skills add identity16/skills

# Claude Code와 Codex 양쪽에 전역으로, 프롬프트 없이 설치
npx skills add identity16/skills -g -a claude-code,codex -y
```

## 스킬 추가하기

`skills/<name>/SKILL.md`를 만듭니다. 새 스킬은 위의 철학을 지켜야 합니다. 작성 규칙은 `CLAUDE.md`에 있습니다. 커밋 전에 `npx skills add . --list`로 발견되는지 확인하고, 이 문서의 스킬 섹션을 갱신하세요.
